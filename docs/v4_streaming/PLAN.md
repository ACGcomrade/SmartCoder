# v0.4 实现前预注册：照片扩增、RAM、统一动态域工厂

2026-09-06。前置研究 RESEARCH.md，旧版 H1–H7 阈值继续保留作为回归。本轮增加到12张真实图像：原6张加 astronaut、camera、brick、grass、gravel、ihc；不是复制、增广或切块凑数量。固定版本来源/哈希、原生分辨率，灰度转RGB。

## 新 hypotheses（实现与真实 RAM 测量之前固定）

| 编号 | 可证伪条件/验收阈值 |
|---|---|
| S1 扩增记忆 | 12张全部从同一最终逻辑 base 原尺寸恢复；量化无额外损失，最大通道误差≤2、PSNR≥42.1102dB。未达即失败 |
| S2 统一工厂 | 不改代码批量生成1、3、6、16、100个域，前缀相同，全部素性正确；照片入库按对自动触发 K=1→…→6，没有每域专属函数；域实例数始终N/2 |
| S3 延迟扩展 | 小状态穷举和照片增长中，每次 append 不读取/修改旧 tile；文件hash不变；显式 lift 与延迟投影相同，旧记忆不丢失；最终与直接CRT参考零差异 |
| S4 局部访问 | open 只读metadata；固定64×64像素tile，16×16 ROI分别测块内/跨边界，最多1/4块；算法记录真实文件读取字节。所有槽局部更新不干扰别的记忆，未命中块hash不变 |
| S5 RAM | 在独立新进程中，对同一12图base做3次 metadata-only、ROI、整域流式、全base紧凑字节载入基线。报告峰值RSS及相对启动高水位增量；ROI增量≤8MiB 且≤max(1MiB,全载增量中位数的25%)。阈值为本次工程假说，不是定理，不通过不得改阈值 |
| S6 面积扩展 | 另用非照片的确定性合成矩阵控制实验：相同K=6、tile64，画布从512²至2048²；固定ROI活动tile数与解压字节数不变，RSS增量相差≤4MiB（工程阈值）。合成数据不计照片数、不宣称整数据集大于物理RAM |
| S7 持久化与边界 | 再开进程恢复无需原图；压缩/未压缩块语义相同，坏CRC/截断拒绝；局部损坏不迫使open全读。旧v0.2/v0.3回归通过 |

## 具体实现边界

一个通用工厂、一个参数化 decoder、一个分块二维存储类。b=6、每域2张；精度变动不在本轮。允许数学工厂Q=2用于手算。K增长采用精确大整数，不让uint64溢出。固定64像素tile；zlib1作为可关闭的无损外层，仅压缩磁盘块，不算降低解压后的RAM。每次最多持有当前块及有限临时副本，无无限块缓存。

先运行小例/测试，再下载并加载新增照片。照片逐对入库，每次仅加载当对输入；完整恢复/评估逐域进行。RAM测试另起不读原图的进程，避免编码/图像展示/先前测试污染峰值。OS缓存冷热不受控，不宣称物理读盘量或I/O延迟；逻辑文件读字节与峰值RSS分别记录。记录编码、解码耗时，但不预设速度优势。

全载基线与按需方法使用相同紧凑大整数字节格式和相同局部结果，不拿Python全量对象列表夸大基线；强制触及全载缓冲页。追加/写入目前单写者，没有跨块事务、并发合并或删除。RAM工作集随K位宽增加；动态方法不是零代价无限记忆。
